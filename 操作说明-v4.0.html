AWACSMARK v4.0 操作说明

适用版本：AWCASMARKER_v4.0_TEST.exe 及同期源码
适用游戏：DCS World 2.9.x（单人 / 多人均可）

v4.0 最大变化：不再截图 + OCR，改为读取 DCS 用户钩子 提供的游戏内文字通报。 识别结果是原始文本，零误识、无延迟、不占显存；程序也不再需要联网做文字识别。

一、程序原理

DCS 里所有显示给玩家的文字（预警机通报、服务器公告、无线电字幕）都会经过 GUI Lua 状态的一组回调。 AWACSMARK 用一个官方支持的用户钩子把这批文字原样写入本地文件，主程序再增量读取、解析、绘制。

DCS 任务脚本 / AI
  trigger.action.outText(...)  /  AWACS 无线电通话
        │
        ▼  GUI Lua 回调（官方 API）
  awacs_hook.lua   ← 放在 Saved Games\DCS\Scripts\Hooks\
  onTriggerMessage / onRadioMessage / onChatMessage
        │  追加写入（每局截断、1 MB 上限、每 5 s 心跳）
        ▼
  %LOCALAPPDATA%\AWACSMARK\messages.log
        │  每 200 ms 只读新增字节（不复读、不重复解析）
        ▼
  AWCASMARKER_v4.0_TEST.exe
  ├─ 协议解析（消息 / 心跳 / 截断标记）
  ├─ 格式路由：auto / SPS 面板 / 传统中文 / 传统英文 / BSC
  ├─ 文本解析：方位、距离、高度、速度、航向、接敌状态
  ├─ 坐标换算：相对本机（BRA）或相对靶眼（Bullseye）→ 绝对坐标
  └─ 雷达绘制（30 fps，按残留时间淡出）

并行两路数据：
  DCS Lua Export（AWCSMARK.lua）──UDP 12345，10 Hz──▶ 本机位置 / 航向 / 高度 / 速度
  队友服务器 ───────────────HTTP──────────────────▶ 友机位置

为什么不再用截图 OCR

对比项截图 + OCR（v3 及以前）DCS 用户钩子（v4）
识别结果有误识（O/0、Km/Kmh、断行）原始字符串，无误差
延迟2–3 秒（截图 + 上传 + 识别）毫秒级（写文件 + 200 ms 轮询）
开销持续截屏、图像编码、上传一次字符串写盘 + 少量读取
依赖远程 OCR 服务器、截图区域必须正确只需本地文件，离线可用
误检桌面/菜单内容可能被识别成敌机只处理游戏内回调的文字

二、文件与脚本位置

文件放到哪里必需作用
awacs_hook.lua <保存的游戏>\DCS\Scripts\Hooks\ 必需 接收游戏内文字并写入日志；DCS 启动时加载
AWCSMARK.lua <保存的游戏>\DCS\Scripts\ 必需 通过 UDP 12345 发送本机飞行数据（10 Hz）
Export.lua <保存的游戏>\DCS\Scripts\ 需修改 加两行挂载上面的 AWCSMARK.lua
AWCASMARKER_v4.0_TEST.exe 任意目录（建议单独文件夹） 必需 主程序
messages.log %LOCALAPPDATA%\AWACSMARK\ 自动生成 钩子写入的文字日志
AWACASConfig.json %LOCALAPPDATA%\ 自动生成 程序设置
app.log <程序目录>\logs\ 自动生成 运行日志（排查用）
“保存的游戏”在哪？通常是 C:\Users\你的用户名\Saved Games\DCS， 但也可能被系统重定向到别的盘（例如 F:\C盘转移\Saved Games\DCS）， 或者叫 DCS.openbeta 等其他名字。
最可靠的办法：在 DCS 里随便截一张图，然后在“保存的游戏”里看哪个文件夹新增了 ScreenShots。

三、安装步骤

  1. 放置消息钩子
    把 awacs_hook.lua 复制到 <保存的游戏>\DCS\Scripts\Hooks\。 没有 Hooks 文件夹就自己新建一个。
    该目录下可能已有 Tacview / SRS / LotAtC 的钩子，互不影响。
  2. 放置飞行数据脚本
    把 AWCSMARK.lua 复制到 <保存的游戏>\DCS\Scripts\。
  3. 在 Export.lua 里挂载
    打开同目录的 Export.lua，在末尾加两行： 
    local lfs = require('lfs')
dofile(lfs.writedir() .. 'Scripts/AWCSMARK.lua')
    如果原来的 AWCSMARK 行是注释状态（以 -- 开头），先删掉旧行再加。
  4. 重启 DCS
    钩子与 Export 脚本只在游戏启动时加载一次，装完必须完全退出并重启游戏。
  5. 运行程序并配置
    双击 AWCASMARKER_v4.0_TEST.exe，点击工具栏 信息查看， 填写代号、靶眼坐标、单位，确认保存。
  6. 开始任务
    进入游戏内任务后，点击程序上的 开始 按钮。 标题栏不再显示“未检测到 DCS 钩子”即表示钩子已连上。

四、设置项说明

设置项说明
代号 (Callsign) 预警机对你的称呼，只填自己的部分。可以填 128，也可以填 Uzi 1-1； 程序会把空格、连字符忽略后比较。
注意：报文里 预警机 (Overlord1-1) 的 Overlord1-1 是预警机自称，不要填。
靶眼坐标 X / Z 任务编辑器里 Bullseye 的坐标。只有“牛眼通报”需要它，不填会导致牛眼目标全部堆在原点。
预警机单位 auto / KM / NM。
SPS、BSC 面板自带单位，auto 会自动识别；
传统预警机通报没有单位，必须手选 KM 或 NM（选 auto 会按 KM 处理并提示一次）。
消息格式 auto（推荐）/ SPS 面板 / 传统(中文) / 传统(英文) / BSC 面板。
SPS、BSC 只是通报的排版格式，与服务器类型无关。认不出格式时可手动锁定。
敌机残留时间 标记在屏幕上保留多少秒（默认 90）。同一目标被再次播报会重新计时。
消息保留窗口 只读取最近多少秒的通报（默认 120，应 ≥ 残留时间）。
小队代码 队友位置共享用，同一个代码的人互相可见。
服务器 队友同步服务器地址；用默认服务器时无需修改。

五、界面操作

位置控件作用
工具栏开始 / 停止启动或停止任务（UDP 监听 + 钩子读取 + 队友同步）
工具栏信息查看打开设置对话框
工具栏模式中心（北向上）/ 直对（机头向上）/ 中心直对
工具栏单位界面显示单位：km 或 nm（只影响显示，不改变解析）
左侧垂直滑块窗口透明度 20%–100%
右侧垂直滑块 + 标签雷达比例尺：50 / 100 / 200 km（或 25 / 50 / 100 nm）
左上角「置顶」复选框窗口始终保持在最前
左上角「数据」复选框切换为飞行数据面板（海拔 / 雷达高度 / 俯仰 / 真空速 / 指示空速）
工具栏简要无边框全屏雷达，可拖动、可调尺寸，适合叠加在游戏画面上

雷达标记怎么看

  • 圆点：敌机位置；颜色越亮越新，随时间从青色渐变为暗蓝直至消失。
  • 圆点旁数字：高度（千单位）。
  • 箭头：敌机航向（由接敌状态推算，SPS 面板直接用通报里的 HDG）。
  • SPS 面板来源：额外显示 M0.78（马赫）和机型编号。
  • 蓝色标记：队友。

六、常见问题

现象原因与处理
雷达上完全没有敌机 先看窗口标题：若显示「未检测到 DCS 钩子」，说明钩子没生效—— 检查 awacs_hook.lua 是否在 Scripts\Hooks\、装完是否重启过 DCS、文件是否有读取权限。
所有敌机都挤在中心 没收到本机飞行数据。检查 Export.lua 是否挂载了 AWCSMARK.lua、是否重启过游戏。
传统预警机的距离明显不对 设置里单位是 auto，但传统通报不含单位。请改选 KM 或 NM。
牛眼目标整体偏移 靶眼坐标填错。核对任务编辑器里的 Bullseye X/Z。
预警机报了点，但程序没反应 多半是呼号没对上：程序只处理“点名给自己”的通报。确认设置里的代号与游戏内一致。
某些通报完全识别不了 把「消息格式」从 auto 改成对应的格式（SPS / 传统 / BSC）再试。
点击「停止」没反应 v4 已修复该问题（旧版是任务队列堆积，跑越久停得越慢）。若仍出现，请附上 logs\app.log。

七、日志与排查

文件用途
%LOCALAPPDATA%\AWACSMARK\messages.log 钩子写入的原始文字。里面有 H 开头的行表示心跳（每 5 秒一行）； M 开头是消息；文件每局开始会清空，最大 1 MB。
<程序目录>\logs\app.log 程序运行日志（DEBUG 级）。会记录钩子连接/失联、每条消息路由到哪种格式、解析结果条数。
排查顺序：
① messages.log 有没有内容 → 没有 = 钩子没装好；
② 有 H 心跳但没有 M → 游戏里没触发通报，或通报走了别的回调；
③ 有 M 但界面没标记 → 看 app.log 里这条消息被路由成了什么、解析出几条。

八、构建（开发者）

.\installpack\Scripts\python.exe -m nuitka ^
  --standalone --onefile ^
  --enable-plugin=pyside6 ^
  --enable-plugin=upx ^
  --upx-binary=".\upx-5.1.1-win64\upx.exe" ^
  --windows-console-mode=disable ^
  --windows-icon-from-ico=./C.gif ^
  --noinclude-dlls=Qt6WebEngineCore.dll ^
  --noinclude-dlls=Qt6WebEngineQuick.dll ^
  --noinclude-dlls=Qt6WebSockets.dll ^
  --noinclude-dlls=Qt6WebChannel.dll ^
  --noinclude-dlls=Qt6WebView.dll ^
  --noinclude-dlls=Qt6Quick.dll ^
  --noinclude-dlls=Qt6Qml.dll ^
  --noinclude-dlls=Qt6Multimedia.dll ^
  --noinclude-dlls=Qt6Positioning.dll ^
  --lto=yes ^
  --output-filename="AWCASMARKER_v4.0_TEST" ^

产物为当前目录下的 AWCASMARKER_v4.0_TEST.exe（首次构建约 5–15 分钟，需要 Nuitka 4.x 与 UPX）。
